# Sensor-fusion literature survey: LiDAR + stereo + 10-axis IMU for RL-controlled humanoid indoor navigation

Compiled 2026-09-23 by a web-research pass for [`SENSOR_FUSION.md`](SENSOR_FUSION.md).
Every reference carries a verification flag: **[V]** the primary page (arXiv
abstract, README, docs or PDF) was fetched; **[M]** only bibliographic metadata
was confirmed via search listings; **[U]** could not be verified. Venue
attributions marked "per my knowledge" were not seen on a fetched page. Treat
the flags as part of the citation. Nothing in this file is a result of this
repository.

## 0. Project-specific framing

- **The sim IMU emits a quantity no physical IMU emits.** Isaac Lab's `ImuData` exposes `projected_gravity_b` and `ang_vel_b` [V]. The physical 10-axis IMU gives raw gyro/accel/mag/baro. An attitude filter must run on hardware to produce the projected-gravity vector before either the frozen gait or the navigation policy can consume it. This is the most direct sim-to-real gap and anchors the ranked list.
- **A walking biped tilts its LiDAR.** AMCL / slam_toolbox / Cartographer-2D assume a level scan. Either gravity-align or reject tilted 2-D scans using the attitude estimate, or use a 3-D LiDAR and slice a horizontal band (`pointcloud_to_laserscan`) to produce the 36-sector observation.
- **3-D LIO methods do not apply to a 2-D LiDAR.** FAST-LIO2 / Point-LIO / GLIM / KISS-ICP READMEs list only 3-D sensors [V].
- **The gait is frozen.** The fused signal feeds a navigation policy over a fixed locomotion controller, so hierarchical nav-over-gait works (Compton et al. 2026, ANYmal Parkour, NaVILA) transfer more directly than end-to-end parkour works.
- **Depth Anything is monocular** (relative depth; metric fine-tunes exist) [V]; it is not a stereo method.
- **The MuJoCo harness models dropout at the command level**, so it cannot exercise estimator-level failures (attitude-filter divergence, scan-matcher lock loss). Sections 5–7 address that.

## 1. Orientation/attitude from a 9/10-axis IMU

- **Madgwick, S. O. H. "An efficient orientation filter for inertial and inertial/magnetic sensor arrays." x-io internal report, 30 Apr 2010.** https://x-io.co.uk/downloads/madgwick_internal_report.pdf [V]. Gradient-descent quaternion filter; IMU (6-axis) and MARG (9-axis) variants; MARG version includes magnetic-distortion and gyro-bias compensation; <0.6° static / <0.8° dynamic RMS. Applies here: the algorithm inside `imu_filter_madgwick`; the IMU-only variant is what you want indoors.
- **Madgwick "Fusion" library.** https://github.com/xioTechnologies/Fusion [V]. Revised AHRS with runtime gyro-bias correction, acceleration rejection, magnetic rejection, start-up gain ramp; C + Python (`imufusion`). Lightest well-maintained option for a microcontroller or non-ROS process.
- **Mahony, R., Hamel, T., Pflimlin, J.-M. "Nonlinear complementary filters on the special orthogonal group." IEEE TAC 53(5):1203–1218, 2008.** [M; citation confirmed via https://ahrs.readthedocs.io/en/latest/filters/mahony.html [V]]. PI correction on SO(3) with gyro-bias estimation. Same accuracy class as Madgwick; the explicit bias integrator is useful for a cheap MEMS gyro.
- **Valenti, R. G., Dryanovski, I., Xiao, J. "Keeping a Good Attitude: A Quaternion-Based Orientation Filter for IMUs and MARGs." Sensors 15(8), 2015.** https://www.mdpi.com/1424-8220/15/8/19302 [M]. Splits the quaternion into roll/pitch (accelerometer) and yaw (magnetometer) parts so magnetic disturbance cannot corrupt inclination. This is `imu_complementary_filter`; the decoupling is what you want when yaw comes from LiDAR.
- **Laidig, D., Seel, T. "VQF: Highly Accurate IMU Orientation Estimation with Bias Estimation and Magnetic Disturbance Rejection." Information Fusion 91, 2023.** https://arxiv.org/abs/2203.17024 [V]; https://github.com/dlaidig/vqf [V] (C++/Python/MATLAB, MIT). 2.9° average RMSE, outperforming all literature filters; 6D and 9D modes; explicit magnetic-disturbance rejection. Best-in-class drop-in for the attitude stage if you wrap a library rather than a ROS node.
- **Caruso, M. et al. "Analysis of the Accuracy of Ten Algorithms for Orientation Estimation ... One Size Does Not Fit All." Sensors 21(7), 2021.** https://www.mdpi.com/1424-8220/21/7/2543 [M]. When optimally tuned, no significant differences among ten filters (3.8–7.1°); default parameters are inadequate. Filter choice matters less than tuning the gain to your walking-induced acceleration profile.
- **Laidig, Caruso, Cereatti, Seel. "BROAD — A Benchmark for Robust Inertial Orientation Estimation." Data 6(7), 2021.** https://github.com/dlaidig/broad [V]. IMU + optical ground truth incl. magnetically disturbed trials, with Python error-metric code. Use its metrics (inclination vs heading split) when validating on mocap.
- **Solà, J. "Quaternion kinematics for the error-state Kalman filter." arXiv 1711.02508, 2017.** https://arxiv.org/abs/1711.02508 [V]. Standard ESKF derivation with IMU bias states and Jacobians; reference if you build a custom ESKF.
- **Forster, Carlone, Dellaert, Scaramuzza. "On-Manifold Preintegration for Real-Time Visual-Inertial Odometry." IEEE TRO 2016.** https://arxiv.org/abs/1512.02363 [V]. Preintegrates high-rate IMU between keyframes on SO(3) as one factor; underpins every factor-graph estimator below.
- **Kok, Hol, Schön. "Using Inertial Sensors for Position and Orientation Estimation." Found. Trends Signal Process. 2017.** https://arxiv.org/abs/1704.06053 [V]. **Kok, Schön. "Magnetometer calibration using inertial sensors." IEEE Sensors J. 2016.** https://arxiv.org/abs/1601.05257 [V]. If you ever enable the magnetometer, calibrate it on the robot; otherwise treat heading as unobservable from IMU alone.
- **Magnetometer indoors.** `imu_filter_madgwick` defaults `use_mag=true`; `imu_complementary_filter` defaults `use_mag=false` [V, source]. Indoor steel and the robot's motors make heading from the magnetometer unreliable; Valenti's decoupling and VQF's rejection limit damage to yaw only. Yaw should come from LiDAR localisation (Section 3), so run the 6D filter with `use_mag=false`; projected gravity depends only on roll/pitch, which the magnetometer cannot improve. (Two indoor-disturbance studies, PMC10221362 and Seel & Ruppin IFAC 2017, were blocked [U].)
- **Barometer.** Zhang, Y., Schwertfeger, S. "Differential Barometric Altimetry for Submeter Vertical Localization and Floor Recognition Indoors." arXiv 2601.02184, 2026. https://arxiv.org/abs/2601.02184 [V]. 0.29 m RMSE, 100 % floor identification: a floor-change detector, not a cm-level base-height signal; base height should come from leg kinematics.
- **ROS 2 packages.** `imu_tools` https://github.com/CCNYRoboticsLab/imu_tools [V] (humble/jazzy/rolling). `imu_filter_madgwick` params [V]: `gain=0.1`, `zeta=0.0`, `use_mag=true`, `world_frame="enu"`, `remove_gravity_vector=false`, `mag_bias_{x,y,z}`, `stateless`, `constant_dt`, `orientation_stddev`. `imu_complementary_filter` [V]: `use_mag=false`, `gain_acc=0.01`, `gain_mag=0.01`, `do_bias_estimation=true`, `bias_alpha=0.01`, `do_adaptive_gain=true` (the adaptive gain down-weights the accelerometer during foot-impact accelerations, which matters on a biped). `robot_localization` https://github.com/cra-ros-pkg/robot_localization [V]: `ekf_node`, `ukf_node`, `navsat_transform_node`; 15-D state; loose-coupling glue (IMU orientation + leg-odometry twist + AMCL pose), not an attitude filter. `fuse` https://github.com/locusrobotics/fuse [V]: plugin factor-graph fusion on Ceres, only if you need online calibration states or delayed measurements. Calibration: `allan_variance_ros` https://github.com/ori-drs/allan_variance_ros [V] (ROS 1); Kalibr IMU noise model https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model [V]: σ_g, σ_a at AD(τ=1 s), bias random walks from the τ=3 s line, inflate static sigmas 10× or more for low-cost MEMS. These four numbers are also the right values for the sim IMU's `NoiseModelWithAdditiveBias` instead of the ad-hoc 0.05/0.02 stds.

## 2. Legged/humanoid base state estimation (IMU + kinematics + contacts)

- **Bloesch et al. "State Estimation for Legged Robots — Consistent Fusion of Leg Kinematics and IMU." RSS 2012.** https://www.roboticsproceedings.org/rss08/p03.html [V]. Observability-constrained EKF over base pose/velocity + footholds; the canonical proprioceptive estimator. The minimal design that yields base linear velocity, which neither the IMU alone nor the raw-channel policy has.
- **Hartley, Ghaffari, Eustice, Grizzle. "Contact-Aided Invariant Extended Kalman Filtering for Robot State Estimation." IJRR 2020.** https://arxiv.org/abs/1904.09251 [V; journal listing M]. InEKF with contact/IMU process model and kinematic corrections; better convergence than quaternion EKF; validated on a bipedal robot. The reference design for a biped.
- **Camurri et al. "Pronto: A Multi-Sensor State Estimator for Legged Robots in Real-World Scenarios." Frontiers 2020.** https://github.com/ori-drs/pronto [V]. Modular EKF fusing IMU + leg odometry + LiDAR/vision; Atlas, Valkyrie, HyQ, ANYmal; **main branch targets ROS 2 Humble (Nov 2025)**. The most directly reusable open humanoid-capable estimator with ROS 2 support.
- **Nobili et al. "Heterogeneous Sensor Fusion for Accurate State Estimation of Dynamic Legged Robots." RSS 2017.** http://www.roboticsproceedings.org/rss13/p07.html [V]. Inertial-driven EKF + probabilistic leg odometry with stereo and LiDAR corrections at different frequencies and latencies; <1 cm/m drift. The architecture for low-rate LiDAR/stereo corrections into a high-rate proprioceptive filter without blocking the controller.
- **Wisth, Camurri, Fallon. "VILENS." IEEE TRO 39(1), 2023.** https://arxiv.org/abs/2107.07243 [V]. Factor graph with leg-velocity bias; 62 %/51 % error reduction vs loosely coupled. Not open-source.
- **Yang et al. "Cerberus: Low-Drift Visual-Inertial-Leg Odometry for Agile Locomotion." ICRA 2023.** https://github.com/ShuoYangRobotics/Cerberus [V]. VINS-Fusion + contact preintegration + online kinematic calibration; <1 % drift; <$1000 sensing; ROS 1. Closest open pattern to "stereo + IMU + legs" on a cheap platform.
- **TSIF** https://github.com/ethz-asl/two_state_information_filter [M: archived Jan 2024]. Historical.
- **Demont et al. "The Kinetics Observer." arXiv 2406.13267, 2024.** https://arxiv.org/abs/2406.13267 [V]. MEKF jointly estimating contact forces and kinematics for humanoids; heavier than needed for a navigation observation.
- **Youm et al. "Legged Robot State Estimation With InEKF Using Neural Measurement Network." arXiv 2402.00366.** https://arxiv.org/abs/2402.00366 [V]. **Lin et al. "Legged Robot State Estimation using Invariant Kalman Filtering and Learned Contact Events." CoRL 2021.** https://arxiv.org/abs/2106.15713 [V]. If the platform lacks foot force sensors, learned contact from joint torque/velocity is the practical route to a contact-aided filter.
- **Buchanan, Camurri, Dellaert, Fallon. "Learning Inertial Odometry for Dynamic Legged Robot State Estimation." CoRL 2021.** https://arxiv.org/abs/2111.00789 [V]. CNN displacement from IMU windows; 37 % error reduction.
- **2025–2026 humanoid-specific and learned estimators.** Baumgartner et al. "CoCo-InEKF: State Estimation with Learned Contact Covariances." RSS 2026, https://arxiv.org/abs/2605.15122 [V] (learned contact-velocity covariances instead of binary contact; research-grade). Feng et al. "FOCUS: Foot Observation Confidence for Robust Humanoid Proprioceptive Odometry." arXiv 2609.02222, 2026, https://arxiv.org/abs/2609.02222 [V] (learned FK-reliability weights into an EKF; 70.8 % real-walking error reduction; no labels or torque sensors; directly targets humanoid foot slip). Hohmeyer et al. "InEKFormer." ICAR 2025, https://arxiv.org/abs/2511.16306 [V]. Mandali, He, Gu. "Proprioceptive Invariant State Estimation for Humanoid Robots on Non-Inertial Ground." https://arxiv.org/abs/2606.19512 [V] (niche here). Dellaert, Noh, Agrawal, Kim. "Four Simple Proprioceptive Estimators for Legged Robots." https://arxiv.org/abs/2605.23100 [V] (contact-aided InEKF through fixed-lag smoother, released in GTSAM with a ROS 2-compatible implementation; the most approachable modern open reference). Girgin, Kilic. "OCELOT." https://arxiv.org/abs/2605.21863 [V] (ES-EKF with GMM/GLRT contact + slip rejection; open-source ROS 2). GAIT https://arxiv.org/abs/2606.14160 [V]; TRACE https://arxiv.org/abs/2608.05975 [V]; Kulkarni, Du, Huang, "Online Learning of Robust Legged Odometry with Minimal Exteroceptive Supervision" https://arxiv.org/abs/2606.21669 [V] (end-to-end learned proprioceptive odometry; research-grade). Nisticò et al. "MUSE." RA-L 2025, https://arxiv.org/abs/2503.12101 [V]. Nubert et al. "Holistic Fusion." TRO (accepted 2026), https://arxiv.org/abs/2504.06479 [V]; https://github.com/leggedrobotics/holistic_fusion (the modern open framework to fuse leg odometry + LiDAR localisation + IMU into one smooth estimate).
- **Bipedal/humanoid LiDAR-inertial-kinematic odometry.** Zhao et al. "LIKO: LiDAR, Inertial, and Kinematic Odometry for Bipedal Robots." arXiv 2404.18047, 2024, https://arxiv.org/abs/2404.18047 [V]; https://github.com/Mr-Zqr/LIKO [V] (built on FAST_LIO, ~1 kHz, BHR-B3 + VLP-16 + Xsens + F/T, VICON dataset). Gao et al. "KILVO: Kinematic-Inertial-LiDAR-Visual Odometry with Robust Multimodal Adaptation for Humanoid Robots." TMECH 2026, https://arxiv.org/abs/2608.05647 [V] (asynchronous-sequential hybrid ES-IKF; LiDAR update before visual update; resilient to sensor failures; code and datasets on GitHub). These two are the closest matches to "bipedal + 3-D LiDAR + IMU + camera"; the asynchronous-sequential ordering is a template for the fusion node. Ou, Li, Li. "Leg-KILO." RA-L 2024, https://github.com/ouguangjun/Leg-KILO [V]. Okawara et al. "Tightly-Coupled LiDAR-IMU-Leg Odometry with Online Learned Leg Kinematics." RA-L 2025, https://arxiv.org/abs/2506.09548 [V].
- **Vendor stacks.** `unitree_ros2` https://github.com/unitreerobotics/unitree_ros2 [V]: `LowState` exposes IMU quaternion/gyro/accel + motor states; estimator closed. Agility Digit / MIT Humanoid estimators: nothing public found [U]. Flayols et al. "Experimental evaluation of simple estimators for humanoid robots." Humanoids 2017, https://hal.science/hal-01574819 [M]. Do not plan on borrowing a vendor estimator.

## 3. LiDAR-inertial / LiDAR-visual-inertial odometry and 2-D localisation

- **3-D LIO (all require a 3-D LiDAR).** Xu, Cai, He, Lin, Zhang. "FAST-LIO2." https://arxiv.org/abs/2107.06829 [V]; https://github.com/hku-mars/FAST_LIO [V] (ikd-Tree, direct registration, up to 100 Hz; runs on Khadas VIM3/TX2/RPi 4B; ROS 1). Default for a Livox Mid-360-class sensor on a small humanoid; LIKO is built on the same codebase. **Point-LIO** https://github.com/hku-mars/Point-LIO [V] (point-by-point updates, IMU as measurement, explicit IMU-saturation handling, 4–8 kHz; ROS Noetic): foot-impact vibration can saturate a cheap IMU, which Point-LIO is designed for. **FAST-LIVO2** https://arxiv.org/abs/2408.14035 [V]; **R3LIVE** https://arxiv.org/abs/2109.07982 [V]; **LVI-SAM** https://arxiv.org/abs/2104.10831 [V] (two subsystems surviving failure of either modality): only if the camera should help odometry too; heavier on Orin than LIO. **Direct LiDAR-Inertial Odometry** https://github.com/vectr-ucla/direct_lidar_inertial_odometry [V] (ROS 2 branch; README stresses LiDAR-IMU time sync). **GLIM** https://github.com/koide3/glim [V] (factor-graph, GPU, native ROS 2): the ROS 2-native GPU LIO that maps well to an Orin. **KISS-ICP** https://github.com/PRBonn/kiss-icp [V] (LiDAR-only, ROS 2, 3-D only): zero-tuning baseline to test whether the IMU actually helps.
- **Visual-inertial.** VINS-Fusion https://github.com/HKUST-Aerial-Robotics/VINS-Fusion [V] (mono/stereo+IMU; online td/extrinsics; ROS 1); OpenVINS https://github.com/rpng/open_vins [V] (MSCKF; ROS 1/2; online extrinsic + time-offset calibration; stereo; ATE/RPE/NEES tooling); Kimera https://arxiv.org/abs/1910.02490 [V]. OpenVINS is the ROS 2-ready stereo-inertial choice if the LiDAR is 2-D and you need 6-DoF odometry.
- **Legged-robot LiDAR SLAM / benchmarks.** Ramezani, Tinchev, Iuganov, Fallon. "Online LiDAR-SLAM for Legged Robots with Robust Registration and Deep-Learned Loop Closure." ICRA 2020, https://arxiv.org/abs/2001.10249 [V]. Tuna et al. "GrandTour: A Legged Robotics Dataset in the Wild." arXiv 2602.18164, 2026, https://arxiv.org/abs/2602.18164 [V]: 63 methods benchmarked (FAST-LIO2, Point-LIO, DLIO, KISS-ICP, OpenVINS, VINS-Fusion, kinematic-inertial odometry, LIVO), ATE/RPE, Mid-360/XT-32/VLP-16, PTP + hardware triggering. The benchmark to pick a LIO for a small legged robot.
- **2-D vs 3-D LiDAR on a small humanoid.** With a 2-D LiDAR you are limited to planar matching: `slam_toolbox` https://github.com/SteveMacenski/slam_toolbox [V] (online/offline/lifelong/localisation modes; needs a 2-D scan + odom TF); `nav2_amcl` https://github.com/ros-navigation/navigation2/tree/main/nav2_amcl [V] (particle filter in a known map from 2-D scan + odom TF); `cartographer_ros` https://google-cartographer-ros.readthedocs.io/en/latest/ [V]. Nav2: Macenski et al. "The Marathon 2." IROS 2020, https://arxiv.org/abs/2003.00368 [V]. **Sway handling:** the classic humanoid solution is 6-D MCL that transforms each 2-D scan by the IMU/kinematic torso pose before matching (Hornung, Wolf, Bennewitz, IROS 2010; `humanoid_localization`) [U: hosts unreachable]; "Localization for humanoid robots with sway compensation in indoor environments" (IEEE 7064277) [M]. **Practical route with a 3-D LiDAR:** run LIO for pose, then `pointcloud_to_laserscan` https://github.com/ros-perception/pointcloud_to_laserscan [V] (ROS 2; `min_height`/`max_height`, `target_frame`) in a gravity-aligned frame to synthesise the exact 36-sector `LaserScan` the policy expects, independent of body pitch/roll. Odometry for AMCL/slam_toolbox must come from leg odometry (Section 2).

## 4. Stereo depth and stereo–LiDAR fusion

- **Hirschmüller. "Stereo Processing by Semiglobal Matching and Mutual Information." TPAMI 2008** [M]; **"Semi-Global Matching — Motivation, Developments and Applications." Photogrammetric Week 2011** https://elib.dlr.de/73119/1/180Hirschmueller.pdf [V]. OpenCV `StereoSGBM` is CPU-only and adequate for 16 pooled features, but fails on textureless walls, which is the maze case; a learned matcher or LiDAR must cover those.
- **Lipson, Teed, Deng. "RAFT-Stereo."** https://arxiv.org/abs/2109.07547 [V]. **Xu et al. "IGEV-Stereo." CVPR 2023.** https://arxiv.org/abs/2303.06615 [V].
- **Wen et al. (NVIDIA) "FoundationStereo: Zero-Shot Stereo Matching." CVPR 2025.** https://arxiv.org/abs/2501.09898 [V]; https://github.com/NVlabs/FoundationStereo [V] (TensorRT FP16 ~6×, tested on Jetson Orin, no absolute Orin FPS published). **Wen, Dewan, Birchfield. "Fast-FoundationStereo." arXiv 2512.11130, 2025.** https://arxiv.org/abs/2512.11130 [V] (>10× faster at near-identical zero-shot accuracy). The one to try on Orin for textureless indoor walls.
- **Yang et al. "Depth Anything V2." NeurIPS 2024.** https://arxiv.org/abs/2406.09414 [V]. Monocular relative depth; without metric scale it cannot produce the ray-cast-equivalent ranges the policy was trained on.
- **NVIDIA Isaac ROS DNN Stereo Depth (ESS).** https://nvidia-isaac-ros.github.io/repositories_and_packages/isaac_ros_dnn_stereo_depth/index.html [V]; performance page [V]: ESS full 576p **66.5 fps / 17 ms on Jetson AGX Orin**, 34.8 fps / 30 ms on Orin Nano Super; ESS light 288p 75.5 fps on AGX Orin. The only stereo DNN with vendor-published Orin latency; confidence output lets you mask unreliable pixels before pooling.
- **Fusion into a map.** Miki et al. "Elevation Mapping for Locomotion and Navigation using GPU." IROS 2022, https://arxiv.org/abs/2204.12876 [V]; https://github.com/leggedrobotics/elevation_mapping_cupy [V]. NVIDIA nvblox https://nvidia-isaac-ros.github.io/repositories_and_packages/isaac_ros_nvblox/index.html [V]: GPU TSDF/ESDF from depth cameras and 3-D LiDAR, Nav2 costmap output; Orin at 5 cm voxels: TSDF 0.8 ms, ESDF 1.7 ms. The stereo–LiDAR fusion that fits this project is a shared gravity-aligned ESDF/elevation map from which both the 36-sector scan and the pooled depth features are re-derived consistently; no direct legged stereo–LiDAR depth-completion paper was found.

## 5. Feeding fused/multi-modal sensing into RL policies

- **Belief encoder (the reference design).** Miki, Lee, Hwangbo, Wellhausen, Koltun, Hutter. "Learning robust perceptive locomotion for quadrupedal robots in the wild." Science Robotics 7(62), 2022. https://arxiv.org/abs/2201.08117 [V; full PDF read]. Teacher with noiseless heights + privileged state; student = GRU belief encoder whose attentional gate controls which aspects of exteroceptive data pass through, trained with behaviour cloning + reconstruction loss. Height noise model with lateral shifts and height perturbations at per-point / per-foot / per-episode scope under three mapping conditions sampled 60/30/10 % (nominal; large per-foot offsets to simulate pose-estimation drift; large per-point noise to simulate occlusion or mapping failure), on a linear curriculum. Ablation: GRU > MLP; gated > non-gated in both noise regimes. The template for fusing 36-sector scan + pooled depth + IMU: recurrent encoder with learned gate, trained under a scan/depth noise curriculum including whole-modality failure.
- **Privileged distillation / adaptation.** Lee et al. Science Robotics 2020 https://arxiv.org/abs/2010.11251 [V]; Chen et al. "Learning by Cheating" CoRL 2019 https://arxiv.org/abs/1912.12294 [V]; Kumar et al. "RMA" RSS 2021 https://arxiv.org/abs/2107.04034 [V]. **Asymmetric actor-critic:** Pinto et al. https://arxiv.org/abs/1710.06542 [V]: critic on full state, actor on sensor input. Train the navigation policy with a critic that sees true pose/map while the actor sees only noisy scan/depth/IMU.
- **Sensor/modality dropout.** Liu, Siravuru, Prabhakar, Veloso, Kantor. "Learning End-to-end Multimodal Sensor Policies for Autonomous Navigation." CoRL 2017. https://arxiv.org/abs/1705.10422 [V]. Sensor Dropout zeroes whole sensor blocks during training; smooth across sensor switching and partial failure. Direct precedent for LiDAR-only / depth-only / IMU-degraded training episodes; the MuJoCo harness can test it, but training must include it.
- **Latency and asynchronous sensors in sim.** Agarwal, Kumar, Malik, Pathak. "Legged Locomotion in Challenging Terrains using Egocentric Vision." CoRL 2022. https://arxiv.org/abs/2211.07638 [V]: real camera captures every 100 ms ± 20 ms; depth pipeline latency 10 ± 10 ms accounted for in phase 2; i.i.d. Gaussian observation noise; policy at 50 Hz. Tan et al. "Sim-to-Real: Learning Agile Locomotion For Quadruped Robots." RSS 2018, https://arxiv.org/abs/1804.10332 [V] (simulating latency). Hwangbo et al. Science Robotics 2019 https://arxiv.org/abs/1901.08652 [V]. Rudin et al. CoRL 2021 https://arxiv.org/abs/2109.11978 [V]. Mittal et al. "Orbit" RA-L 2023 https://arxiv.org/abs/2301.04195 [V]. Isaac Lab tooling: per-sensor `update_period` with asynchronous refresh [V]; `DelayBuffer` with per-environment random lag [V]; `GaussianNoiseCfg` / `UniformNoiseCfg` / `NoiseModelWithAdditiveBiasCfg` (bias resampled at reset) [V]. Our IMU noise (0.05/0.02) has no bias term and no delay; add `NoiseModelWithAdditiveBias` with kalibr-derived sigmas, run LiDAR/depth at their real rates, and delay them with `DelayBuffer`.
- **Domain randomisation.** Peng et al. ICRA 2018 https://arxiv.org/abs/1710.06537 [V].
- **Hierarchical navigation over a fixed gait (closest to this project).** Compton, Olkin, Bena, Ames. "Learning Safe Humanoid Navigation from Reduced Order Models." arXiv 2609.19272, 2026, https://arxiv.org/abs/2609.19272 [V]: navigation policy trained on reduced-order dynamics with **3-D LiDAR**, transferred to a Unitree G1 **with a frozen locomotion policy**, plus a Poisson safety filter; mapless multi-floor traversal. Near-exact analogue of our setup; read first. Compton, Olkin, Ames. "Terrain Consistent Reference-Guided RL for Humanoid Navigation Autonomy." https://arxiv.org/abs/2605.15517 [V]. Hoeller, Rudin, Sako, Hutter. "ANYmal Parkour." https://arxiv.org/abs/2306.14874 [V]. Miki, Lee, Wellhausen, Hutter. "Learning to walk in confined spaces using 3D representation." ICRA 2024, https://arxiv.org/abs/2403.00187 [V] (voxel occupancy for a high-level policy issuing commands to a low-level controller). Cheng et al. "NaVILA." https://arxiv.org/abs/2412.04453 [V]. Steinmetz et al. "World Models for Autonomous Navigation of Terrestrial Robots from LIDAR Observations." 2025, https://arxiv.org/abs/2512.03429 [V] (DreamerV3 over 2-D LiDAR). Hou et al. "RAVEN." https://arxiv.org/abs/2607.15701 [V].
- **Humanoid perceptive locomotion with LiDAR/depth (2024–2026).** Long et al. "Learning Humanoid Locomotion with Perceptive Internal Model." https://arxiv.org/abs/2411.14386 [V] (LiDAR-based elevation map; Hybrid Internal Model https://arxiv.org/abs/2312.11460 [V]). ## 7. Evaluation methodology

- **Datasets.** GrandTour [V]; Hilti SLAM Challenge (Helmberger et al. RA-L 2022) https://arxiv.org/abs/2109.11316 [V] (indoor offices/labs, mm ground truth); LIKO bipedal dataset [V]; KILVO humanoid datasets [V]; Leg-KILO [V]; EuRoC [M]; BROAD [V]. - **Validating the fusion stack before it feeds the controller.** (i) attitude filter vs mocap on walking data with foot impacts, inclination/heading split; (ii) leg-odometry velocity vs mocap-differentiated velocity; (iii) LiDAR pose vs mocap or known maze map (evo); (iv) replay the logged sensor tuple through the observation assembler and compare the synthesised 36-sector scan / pooled depth to Isaac Lab ray-cast values on a digital twin of the maze (distribution match, not just error); (v) closed-loop in the MuJoCo harness with **estimator-level** failures injected (attitude divergence, scan-matcher lock loss), not only command-level dropout.
- **Ablations isolating each modality.** Miki 2022: gated vs non-gated, MLP vs GRU, small/large noise [V]; VILENS: tight vs loose [V]; Cerberus: with/without leg factor [V]; Caruso 2021: tuned vs default [M]; Agarwal 2022: "Blind" and "Noisy" baselines [V]. ## What to adopt first (ranked)

1. **Attitude filter that synthesises the policy's IMU observation on hardware — mature, off-the-shelf.** `imu_complementary_filter` (or `imu_filter_madgwick` with `use_mag=false`) from `imu_tools`, or VQF as a library; derive `projected_gravity_b = Rᵀ[0,0,−1]` and body rates. The sim IMU publishes projected gravity; the physical IMU does not; nothing else matters until this observation exists. Tune the gain on walking data vs mocap (Caruso: tuning dominates filter choice). Ignore the magnetometer indoors; the barometer is a floor-change flag only.
2. **Time base and calibration before any fusion — mature.** Kalibr (stereo + camera-IMU spatial/temporal, with `allan_variance_ros` sigmas inflated per the kalibr noise-model page), LI-Init for LiDAR-IMU, `direct_visual_lidar_calibration` for LiDAR-camera, driver-side timestamps for the USB IMU, PTP on the LiDAR if supported. The kalibr sigmas also become the sim IMU noise/bias parameters.
3. **Make the simulator's sensor timing and noise honest — mature tooling, cheap retrain.** `NoiseModelWithAdditiveBias` on IMU terms, real `update_period` for scan/depth, `DelayBuffer` lags mirroring measured latencies, DPL-style holes/self-occlusion on ray-cast depth. The harness currently randomises command-level dropout only; sensor timing is the documented transfer gap (Tan 2018, Agarwal 2022, DPL 2026).
4. **Pose/heading and the 36-sector observation from LiDAR — mature.** 3-D LiDAR (Mid-360 class): FAST-LIO2 (Point-LIO if foot impacts saturate the IMU; GLIM for native ROS 2 + GPU) → `pointcloud_to_laserscan` in a gravity-aligned frame → slam_toolbox/AMCL for map-relative yaw/position. 2-D LiDAR only: tilt-compensate scans with the attitude estimate before slam_toolbox/AMCL; odometry must come from legs.
5. **Proprioceptive base estimator (IMU + kinematics + contact) — off-the-shelf filters, research-grade contact handling.** Pronto (ROS 2 Humble) or the GTSAM "Four Simple Proprioceptive Estimators"; feed velocity to the navigation policy and odometry to slam_toolbox/AMCL. Contact reliability for a small biped without foot sensors is the open research (FOCUS, CoCo-InEKF, Lin et al.); treat as follow-on.
6. **Belief-encoder fusion with a noise curriculum and modality dropout — research-grade but well-trodden.** Re-train the navigation policy as a Miki-style student: GRU + attention gate over {scan, pooled depth, IMU}, teacher with privileged pose/map, noise model with whole-modality failure episodes (60/30/10), Sensor-Dropout block zeroing, asymmetric critic. Maps one-to-one onto Compton et al.'s frozen-gait G1 setup.
7. **Stereo depth on Orin — off-the-shelf.** Isaac ROS ESS (66.5 fps / 17 ms at 576p on AGX Orin, confidence-masked) or Fast-FoundationStereo via TensorRT for textureless walls; pool to 16 features from a gravity-aligned band, or fuse into nvblox/elevation map and re-derive both scan and depth features from one map so the two exteroceptive channels stay geometrically consistent, as they are in sim.
8. **Evaluation loop — mature.** evo/rpg ATE-RPE (PosYaw), BROAD-style orientation RMSE, NEES for any consumed covariance, offline replays on LIKO/KILVO/GrandTour, and a modality-ablation matrix in the MuJoCo harness extended with estimator-level failure injection.
