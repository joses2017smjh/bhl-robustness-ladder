# Native ORB-SLAM3 stereo runtime — 2026-10-09

This campaign uses the actual ORB-SLAM3 C++ stereo tracking, local mapping,
loop closure, feature extraction, DBoW2 and g2o implementation pinned at
[`4452a3c4`](https://github.com/UZ-SLAMLab/ORB_SLAM3/tree/4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4).
The earlier October 8 work prepared replay inputs; it did not run this estimator.
Build completion and scientific replay outcomes are separate receipts.

The research basis is [Campos et al., ORB-SLAM3](https://arxiv.org/abs/2007.11898),
which describes stereo tracking and recovery across multiple maps. Our campaign
therefore retains native tracking states/map identifiers and scores continuous
maps separately: this is our evaluation design for exposing loss/recovery,
rather than silently aligning across a reset. All reported accuracy and latency
must come from our retained replay outputs and fixed simulation protocol.

## Private, headless build

`scripts/native/orb_build.py` runs in the existing Ubuntu 22.04 SIF on an
allocated CPU job. It downloads and extracts Ubuntu development packages into
a private sysroot. It does not modify the container, system packages or the
shared Python environment. Exact archive SHA-256 values, package versions,
compiler version, upstream commit and linked libraries are saved in `runtime.json`.
The container itself is independently hashed by the campaign launcher.

The upstream algorithm source files are unchanged. The build omits upstream
`Viewer.cc` and `MapDrawer.cc` and links `orb_headless.cc` in their place.
Three visualization includes are removed/forward-declared to avoid requiring
Pangolin; the map viewer-thumbnail byte type retains its identical
`unsigned char` alias. The headless map drawer retains `SetCurrentCameraPose`; drawing does
nothing, and constructing a viewer throws an error. The runner passes
`bUseViewer=false`. No display is created and no pose is generated by these
visualization replacements. Exact modifications and source are archived.
The third-party CMake flags remove `-march=native` and use `-O2`, allowing the
runtime to move between CPU models without changing estimator logic.

The upstream documentation identifies Pangolin as the visualization dependency
and provides native stereo examples and calibration requirements:
[upstream README](https://github.com/UZ-SLAMLab/ORB_SLAM3/blob/4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4/README.md).
The build retains ORB-SLAM3's GPL-3.0 license, the exact patched upstream source,
and the adapter C++ source alongside the binary. Original vocabulary contents
are extracted from the pinned upstream archive and independently hashed.

Example build command **inside the SIF and an allocated CPU job**:

```bash
python scripts/native/orb_build.py \
  --work /tmp/orb-build-example --output /tmp/orb-runtime-example --jobs 2
```

The paths must be new. The v4 launcher reserves two CPUs and 32 GB RAM,
with explicit `--jobs 2` matching that allocation. Compilation runs only in an
allocated Slurm job or a separately recorded resource-limited Slurm step.
`runtime.json:status=PASS`
requires successful compilation, a real executable version smoke, and resolved
`ldd` dependencies. It does not imply successful camera initialization.

Build attempts remain versioned. V1 was cancelled while archiving unrelated
upstream example recordings; v2 exposed a missing viewer-thumbnail byte typedef
after removing the Pangolin include. V3 restored the identical type alias but
was cancelled while still pending. V4 changes only build CPU parallelism to
obtain an available scheduler slot. The original diagnostics, cancellation
receipts, frozen sources and exact resource protocols remain under
[`results/native-campaign-20261009`](../results/native-campaign-20261009/).

## Original images and time, per-frame native state

`orb_runner.cc` constructs `ORB_SLAM3::System` in `STEREO` mode. It reads
original rectified PNG pairs, converts OpenCV BGR decoding to RGB to match the
exported calibration settings, and calls upstream `TrackStereo` with each
original sensor timestamp. OpenCV internal image work uses one CPU thread;
upstream local mapping and loop closure remain enabled.

Each stdin request is exactly three tab-separated fields:

```text
timestamp_s<TAB>absolute_left_png<TAB>absolute_right_png<NEWLINE>
```

The native program writes JSON lines to a dedicated regular file or FIFO passed
as its third argument. Upstream diagnostics stay on stdout/stderr, so they
cannot be mistaken for measurements. The readiness line records the upstream
commit. Every subsequent image pair produces a response such as:

```json
{"schema":"bhl-orb-native-frame-v1","timestamp_s":0.1,"tracking_state":1,"tracked":false,"compute_seconds":0.02,"map_id":null,"T_W_C":null}
```

`tracking_state` is the actual upstream state: `-1 SYSTEM_NOT_READY`,
`0 NO_IMAGES_YET`, `1 NOT_INITIALIZED`, `2 OK`, `3 RECENTLY_LOST`, `4 LOST`,
or `5 OK_KLT`. This strict stereo campaign accepts only `OK` as tracked.
For tracked frames, `T_W_C` is the inverse of the actual `TrackStereo` return:
it maps left optical camera coordinates into native map coordinates. For all
other frames it is null. A native map identifier is read from the first valid
tracked map point; unavailable identifiers remain null. This is read-only
instrumentation and does not supply a pose or alter the estimator.

The native compute duration includes PNG decode, RGB conversion, native
tracking and response preparation, measured with a monotonic clock. It excludes
capture, transport, controller execution and queued mapping/loop-closure work;
it must not be described as sensor-to-actuation latency.

## Python streaming boundary

Inside the SIF, with the runtime's `lib` directory on `LD_LIBRARY_PATH`:

```python
from bhl_robust.research.native_orb import NativeOrbClient, tracking_summary

with NativeOrbClient(runtime / "bin/orb_native", runtime / "ORBvoc.txt",
                     stereo_settings, new_episode_directory) as estimator:
    response = estimator.track(timestamp_s, left_png, right_png)
    # Persist every response, including null/uninitialized/lost estimates.
```

The context manager stores native diagnostics in `native-orb.log`, creates a
private FIFO, verifies runtime readiness/pin and rejects mismatched response
times, invalid states, scaled/non-finite rotations and poses on lost frames.
Only image paths and timestamps cross the per-frame estimator boundary; no
truth poses, depth, lidar or IMU arrays are supplied to this stereo method.
The module does not create a synthetic pose when tracking fails.

Native map coordinates have an arbitrary origin. A closed-loop consumer must
register the first valid pose using declared camera/body calibration and its
known start convention, reject unregistered/lost/stale packets and reject map
changes. It must not use evaluator poses to initialize or correct the estimator.
An offline evaluator can independently align metric trajectories for ATE/RPE;
that alignment is never returned to the online controller.

## Scoring and limitations

Upstream stereo initialization requires more than 500 extracted features in
the current frame ([pinned Tracking.cc](https://github.com/UZ-SLAMLab/ORB_SLAM3/blob/4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4/src/Tracking.cc)).
The new campaign therefore declares 640 × 480 original capture and textured
surfaces before replay; it does not lower initialization thresholds after seeing
results. Failed initialization is a valid negative experimental outcome.

All native statuses, map changes, original timestamps, per-frame latencies,
vocabulary/configuration/runtime hashes and original inference file hashes must
be retained. Score each continuous map independently; do not hide a reset by
fitting one rigid alignment across unrelated maps. Do not compute ATE/RPE when
fewer than two actual tracked poses are available. Simulation replay validates
the integration and provides simulation measurements; it does not establish
physical stereo SLAM performance or LiDAR–IMU performance.

`tests/test_native_orb.py` exercises response validation and subprocess/FIFO
failure handling. Its explicitly labeled fixture processes validate the IPC
contract; they are not estimators and are never counted as campaign outputs.

The v5 backup attempt, **job 21741510**, requested two CPUs, 16 GiB RAM,
90 minutes, the accessible CPU `preempt` partition, and `--no-requeue`.
V4 was cancelled only while pending. The source-equivalence receipt preserves

changes scheduling resources. A preemption is an incomplete attempt.

The shared `write_rectified_stereo_settings` helper therefore uses upstream's
supported legacy `PinHole` parser, omitting `File.version` and providing the
same camera intrinsics, zero distortion, `Camera.bf = fx * baseline`, and
`ThDepth = 40`. The original baseline, images, 1200-feature recipe, FAST 20/7,
native binary and scientific gates remain unchanged. `Stereo.*` values are
retained as audit annotations; the legacy tracker consumes `Camera.bf`.

**Step 21739893.6** verified this calibration-schema repair with the actual
native constructor: it loaded the vocabulary and atlas, printed the declared
camera/feature parameters, emitted genuine READY, and shut down on EOF with
exit 0. This startup check uses no images or scientific scores. Fresh v2

terminate jobs whose afterok dependency cannot succeed.


## Completed native replay measurements

The actual full campaign, **step 21739893.8**, completed all **450/450**
original stereo pairs. The independent collection audit is PASS; scientific
qualification is **NEGATIVE overall (1/3 scene groups passed)**. Textured boxes
(development) and thin posts (validation) each returned 150 NOT_INITIALIZED
states with null poses. The heldout ramp/step scene returned 28 uninitialized
frames followed by 122 OK frames, with no map reset; tracking after the declared
first 5 seconds was 97.6%, metric ATE RMSE 4.39 mm, rotation ATE p95 0.640 degrees,
and native compute p95 48.60 ms. ATE is unavailable in the other scenes because
no estimated trajectory exists. These are bounded simulated replay results;
there is no hardware or closed-loop navigation claim and no post-output tuning.
The full [verified collection](../results/native-campaign-20261009/orb-replay-v2/collection/report.md)
retains original states, null poses, timestamps and native process logs.
